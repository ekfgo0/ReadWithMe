# Lessons Learned

> 각 항목의 자세한 사항은 최종 보고서에 기술하였습니다.

## 요구사항 명세화가 AI 프롬프트 품질에 미친 영향

요구사항이 구체적일수록 AI가 생성하는 코드의 품질이 높아졌다. 단순히 "독서 기록 시스템을 만들어줘"라고 요청하는 것보다, 입력 항목, 필수값, 예외 처리, 저장 방식, 검색·정렬 기준을 명확히 제시했을 때 실제 요구사항에 가까운 결과를 얻을 수 있었다.

특히 진도율 기반 상태 자동 계산(0% 읽고 싶음 / 1~99% 읽는 중 / 100% 완독) 기준을 명확히 정의하자 AI가 단순 입력 폼이 아니라 상태 계산과 예외 처리까지 포함한 코드를 생성할 수 있었다. 또한 `readWithMeBooks`라는 공통 localStorage 키와 데이터 구조를 팀 내에서 먼저 합의하고 정의함으로써, 서재 탭과 통계 탭이 독서 기록 탭의 데이터를 기준으로 기능을 구현할 수 있었다. 요구사항 명세가 AI 활용뿐만 아니라 팀원 간 기능 연동의 기준이 된다는 점을 확인할 수 있었다.

## 브랜치 전략 적용 효과 및 통합 경험

기능별 브랜치(feat/layout, feat/record, feat/library, feat/statistics)를 분리한 덕분에 각 팀원이 독립적으로 개발할 수 있었다. feat/layout이 공통 레이아웃과 탭 네비게이션 구조를 먼저 제공했기 때문에 나머지 브랜치가 같은 구조 위에서 기능을 구현할 수 있었다.

통합 과정에서는 실제 구현 코드와 임시 placeholder 코드를 구분하여 정리하는 작업이 필요했다. 각 브랜치에서 작성한 코드의 역할과 우선순위를 판단하고, 최종 기능에 필요한 코드를 기준으로 정리하는 과정을 통해 브랜치 전략은 단순한 작업 분리가 아니라 기능 간 의존성과 통합 시 코드 우선순위를 판단하는 과정까지 포함한다는 점을 직접 경험하였다.

## localStorage 방식의 한계

localStorage는 구현이 간단하고 새로고침 후에도 데이터가 유지되어 프론트엔드 중심 프로젝트에 적합했다. 실제로 독서 기록 탭에서 저장한 데이터가 서재 탭과 통계 탭에서 즉시 반영되는 구조를 간단하게 구현할 수 있었다.

그러나 localStorage는 특정 브라우저에만 데이터가 저장되므로 다른 기기나 브라우저와 동기화되지 않는다. 브라우저 저장 데이터를 삭제하면 기록도 함께 사라지며, 사용자 계정별 데이터 관리도 어렵다. 이번 프로젝트 범위에서는 적절한 선택이었지만, 실제 서비스로 확장하려면 계정 기반 저장, 서버 API, 데이터베이스 연동이 필요하다는 한계를 명확히 인식하게 되었다.

## 바이브코딩의 장단점

바이브코딩은 개발 속도를 높이는 데 큰 도움이 되었다. React 컴포넌트 구조, 탭 네비게이션, 입력 폼, localStorage 저장 로직, 검색·정렬 로직, 통계 데이터 연결 방식까지 빠르게 구현할 수 있었다. 또한 기능 간 연결 관계를 정리하는 데도 유용했으며, Git과 브랜치 사용에 익숙하지 않은 상황에서 단계별 명령어를 확인하며 작업할 수 있었다.

반면 AI는 실제 파일 구조나 브랜치 상태를 완전히 알지 못한다는 한계가 있었다. 실제 저장소에 React 구조가 없는 상태에서 AI가 이미 구조가 있다고 가정하고 코드를 생성하는 경우도 있었다. 결국 바이브코딩은 개발자가 요구사항과 프로젝트 상태를 정확히 이해한 상태에서 활용해야 효과적인 도구라는 점을 깨달았다.

## 프로세스 없이 바이브코딩했다면?

요구사항 분석, 설계, 브랜치 전략, 테스트 기준 없이 바이브코딩만 사용했다면 기능 간 데이터 구조 충돌, 화면 구조 중복, 테스트 누락이 발생했을 것이다. 예를 들어 독서 기록 탭에서 저장한 데이터 구조와 서재·통계 탭에서 기대하는 구조가 달랐다면 통합 과정에서 제대로 동작하지 않았을 것이다.

또한 통계 기능의 동일 날짜 중복 처리 기준, 상태별 필터링 방식 등 세부 기준이 없었다면 각 기능이 서로 다른 방식으로 구현되었을 가능성이 높다. 이번 프로젝트를 통해 바이브코딩은 소프트웨어공학 프로세스를 대체하는 것이 아니라, 요구사항 분석과 설계가 정리된 상태에서 사용할 때 가장 효과적임을 확인하였다.
